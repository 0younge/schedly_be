# Code Rules

Read before writing or changing code.

- Favor maintainable code: clear names, small units, simple control flow.
- Favor extensible code: isolate policies, boundaries, and external dependencies.
- Follow existing project style before adding abstractions.
- Add abstractions only when they reduce real duplication or clarify ownership.
- Keep behavior testable; verify the smallest meaningful unit.
- Avoid hard-coded secrets, URLs, credentials, and environment-specific values.
